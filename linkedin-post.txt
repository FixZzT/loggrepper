grep -B 20 -A 20 no sabe cuánto tiempo cubre. loggrepper sí.

Cansado de que `grep ERROR app.log` te tire solo la línea del error y nada de contexto. `-B` y `-A` asumen que N líneas = N segundos, pero en logs reales eso nunca se cumple. Si el log es verboso, 20 líneas no cubren ni un segundo. Si es escaso, 20 líneas son puro ruido.

Armé loggrepper, un grep contextual que trabaja con timestamps reales en vez de contar líneas.

  loggrepper ERROR app.log -w 5

Te devuelve todas las líneas cuyo timestamp está dentro de ±5 segundos del match. Las líneas sueltas se agrupan en incidentes, las ventanas solapadas se fusionan, y cada incidente muestra su rango temporal real.

Qué lo hace distinto:

- Detecta automáticamente el formato de timestamp (ISO8601, syslog, nginx, epoch-ms). Si no, lo especificás con --ts-format.
- Salida JSON para scripts: loggrepper ERROR app.log -o json | jq
- Funciona con pipes: docker logs mi-app 2>&1 | loggrepper FATAL -
- Marca con >>> las líneas que coinciden con el patrón. Todo lo demás es contexto real.

Casos donde salva horas:

Depurar un IntegrityError y ver el request completo, el SQL, el rollback y el 500 — todo en una ventana de 5s. Sin adivinar flags de grep.

Investigar un timeout entre microservicios y darte cuenta en segundos de que Stripe tardó 8s en responder. No era tu código.

Auditar requests sospechosos en nginx con ventana de 30s, directo a JSON para procesar.

El proyecto es open source (MIT), está en PyPI, tiene CI/CD y 14 tests. Lo armé en Python sin dependencias externas.

Repo: https://github.com/FixZzT/loggrepper
